# Feature: WorkOrders (Наряды → Действующие / Выполненные)

- Легаси: нет (пункт меню есть в `mainForm.Designer.vb`, форма-заглушка `CompletedOrders` пустая)
- Цель: `Views/WorkOrdersView.xaml`, `ViewModels/WorkOrdersViewModel.cs`,
  `Data/WorkOrderRepository`, `Models/WorkOrderModels`, `Domain/WorkOrderRules`
- Статус: карточка (код не начат)
- Зависимости: `IDbConnectionFactory` (вторая БД), `IDialogService`; внешняя БД
  `Движение по ВЦ. НП.accdb`; меню «Основные данные → Наряды»

## 1. Назначение и сценарии
Просмотр и корректировка нарядов вязального цеха из внешней Access-БД.
- «Действующие» — наряды, по которым ещё не выполнен план (не закрыты).
- «Выполненные» — наряды с выполненным/перевыполненным планом.
- Список: поиск по коду наряда/заказу/артикулу/заказчику, фильтр по дате наряда,
  сортировка по дате (новые сверху), прогресс и остаток.
- Карточка наряда: просмотр реквизитов, правка факта, веса, даты вязания,
  вязальщиц и процентов, ВТО/стирки и дат, новых роста/размера; сохранение в `Наряды`.
- «Отметить выполненным»: факт = план (если план > 0), дата вязания = сегодня, сохранение.
- Сводка по заказу выбранного наряда: заказано / выдано / связано / осталось выдать /
  довязать / в цеху (аналог подчиненной формы `ВыполнениеЗаказовNEWростРазмер`).

## 4. Данные (внешняя БД, ACE)
- `НарядыЗапрос` (сохранённый запрос): IDнаряда, Заказ, ДатаНаряда, №наряда, КодНаряда,
  №машины, Рост/РостNEW/Рост1, Размер/РазмерNEW/Размер1, ПланКол-во, ФактКол-во, ФактВес,
  ДатаНарядаФакт, Вязальщица1..3, Вяз1..3%, ВТО1, ДатаВТОФакт, Стирка1, ДатаСтиркиФакт,
  Испорчен, В печать, Отпечатано (запрос уже исключает Испорчен=Yes).
- `ЗаказыЗапрос`: Заказ, Заказчики.Заказчик, Артикул, Цвет, Оборудование, ДатаЗаказа.
- `ЗаказыИнфо`: SUM(ЗаказКол-во) по Заказ (план заказа; Испорчен=False).
- `Вязальщицы`, `Формировщицы`: справочники ID/ФИО.
- Чтение: параметров нет; `ORDER BY IDнаряда DESC`.
- Запись: `UPDATE [Наряды] SET [ФактКол-во]=?, [ФактВес]=?, [ДатаНарядаФакт]=?,
  [РостNEW]=?, [РазмерNEW]=?, [Вязальщица1]=?, [Вяз1%]=?, ... WHERE [IDнаряда]=?`
  одной командой, без транзакции (одна строка). Все значения параметризованы.

## 5. Бизнес-правила и формулы
- Выполнен, если `ПланКол-во > 0 && ФактКол-во >= ПланКол-во`, либо
  `ПланКол-во <= 0 && ФактКол-во > 0` (аномалии с нулевым планом).
- «Действующие» = не выполненные; «Выполненные» = выполненные.
- Прогресс: `min(100, Факт/План*100)`; при плане 0 — 100, если факт > 0, иначе 0.
- Остаток: `max(0, План-Факт)`; для сводки заказа: `Заказано-Выдано`, `Заказано-Связано`,
  `Выдано-Связано` (может быть отрицательным, как в Access-запросе).
- Проценты вязальщиц — Currency; допускаются дробные, 0..100. Пустой ФИО → ID и % = NULL/0.
- Числа парсятся с `,`/`.` (ru-RU), пустое → 0/NULL; вес и проценты — decimal, не double.
- Даты сохраняются как дата без времени (`Date`); пустая дата → NULL.

## 6. Валидация и edge cases
- Факт < 0, вес < 0, процент вне 0..100, неверный формат — сообщение, сохранение блокируется.
- Факт больше плана разрешён (перевыполнение), наряд считается выполненным.
- План = 0: факт 0 — действующий, факт > 0 — выполненный; «Отметить выполненным» ставит факт=1.
- Внешняя БД недоступна/нет ACE/файл занят: «Ошибка подключения к БД нарядов: …», список пуст.
- Пустой результат: «Наряды по заданным критериям не найдены.».
- Ошибка UPDATE: «Ошибка при сохранении наряда: …», карточка остаётся открытой.
- После сохранения наряд может выйти из текущего режима — список перечитывается.

## 7. Навигация и поведение окна
Меню «Основные данные → Наряды → Действующие/Выполненные» → один `WorkOrdersView`
с режимом из `MainWindowViewModel`. Внутри — список и карточка (переключение панелей).
Возврат к списку — «Отмена»/«Назад»; пункт меню всегда открывает свежий экран.
